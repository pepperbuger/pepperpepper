# 프로젝트 개요: Ondo + Lighter 유동성 리워드 봇

## 한 줄 요약

Ondo Perps에 호가를 걸어 유동성 리워드를 측정하고, 체결분은 Lighter에서 반대로 헷지해 방향 위험을 줄이는 봇이다. 실제 비용과 잔여 위험도 함께 기록한다.

## 왜 하는가

2026-10-30 최신 요청은 실주문 재개 없이 BTC·ETH의 5/10/18bps를 새 수집부터 7일 비교하는 것이다. [비교 가정·비용·결과 표](docs/PAPER_COMPARISON.md)를 따른다. 기존 LIT·ENA는 별도 승인된4건으로 모두 정리했고, 최종 포지션·활성 주문·미확정0이다. [정리 결과](docs/POSITION_CLOSE_RESULT.md)의 순비용은0.875544USDC다. 비교 판단 기준은500USD 자본에서 같은 거리의 BTC+ETH 주2USDC 순이익이다.

2026-10-30 주의: 이번 주 공식 유동성 보상 대상에 LIT·ENA가 없다. 기존 설정의 얇은 호가만 보고 보상 수익을 기대하면 안 된다. 18bps는 대상 마켓 풀에서도 5% 구간이며, [주간 측정 계획](docs/REWARD_WEEK_PLAN.md)에 공식 기준·공개 호가 시나리오·실주문 재개 조건을 정리했다. 현재 실주문은 정지 상태이며 10월 30일 08:13 KST부터 11월 6일 08:13까지 공개 관측을 시작했다.

Ondo Perps는 아직 공개 베타라 거래소를 키우려고 매주 리워드를 뿌리고 있다.

| 리워드 | 주간 규모 | 받는 조건 |
|---|---|---|
| 유동성 풀 | 10만 USDC | 시장가 근처에 지정가 호가를 걸어두기만 하면 됨 (체결 안 돼도 됨) |
| 거래량 풀 | 10만 USDC | Ondo에서 거래한 금액만큼 |
| 액티비티 풀 | 2만 USDC | 화면에서 확인 못 함 |
| Ondo 포인트 | 500만 포인트 | 거래 활동 기준, 가치 미정 |

여기서 노리는 건 유동성 풀이다. 호가를 걸어두는 것만으로 돈을 주니, 체결을 많이 받을 필요가 없다. 속도 경쟁이 아니라 "얼마나 오래, 얼마나 얇은 마켓에 걸어두느냐"의 싸움이라 개인 봇이 낄 자리가 있다.

문제는 호가가 체결되면 원하지 않는 포지션이 생긴다는 점이다. 이걸 Lighter에서 반대로 잡아 상쇄한다. 헷지 비용은 실제 체결 가격과 자산 변화로 측정하며, 거래 수수료가 없다는 가정만으로 비용을 0으로 잡지 않는다.

## 어떻게 돈이 나오는가

```
            호가를 걸어둠 (post-only)
   [봇] ───────────────────────────────> [Ondo Perps]
     │                                      │
     │  매주 USDC 리워드 + 포인트 <────────┘
     │
     │  체결 알림이 오면
     │
     │  즉시 반대 방향 주문
     └───────────────────────────────> [Lighter]

   목표: Ondo 포지션 + Lighter 포지션 = 0  -> 방향 위험 감소 (괴리·펀딩·체결 비용은 남음)
```

수익 = 유동성 리워드 + 거래량 리워드 - Ondo maker 수수료 - 헷지 때 밀리는 비용 ± 펀딩

## 무엇을 만드는가

하나의 Python 프로그램이 집 PC에서 24시간 돌아간다.

| 부품 | 하는 일 |
|---|---|
| 시세 수신 | Ondo와 Lighter 가격을 실시간으로 받아 두 거래소 가격 차이를 감시 |
| 호가기 | 시장가에서 약 0.18% 떨어진 곳에 매수, 매도 호가를 걸고 가격이 움직이면 다시 건다 |
| 헷지기 | Ondo에서 체결되면 Lighter에서 즉시 반대 포지션을 잡는다 |
| 안전장치 | 헷지가 깨지거나 연결이 끊기거나 손실이 한도를 넘으면 호가를 전부 내리고 멈춘다 |
| 기록기 | 호가, 체결, 헷지 비용, 펀딩, 받은 리워드를 전부 저장하고 주간 리포트를 만든다 |

이미 있는 것: 설계서(`docs/SPEC.md`), Claude Code 작업 규칙(`CLAUDE.md`), 설정 템플릿, 마켓 선별 측정기(`scripts/ondo_depth_probe.py`), 그리고 봇 전체 코드(설정 검증, 시세 수신, 호가기, 헷지기, 안전장치, 기록과 리포트). 실제 키 인증·주문 조회와 10분 dry_run을 확인했다. 2026-10-29에는 Ondo 열린 호가를 둔 시험 프로세스를 강제 종료하고 26.718초 후 자동 취소를 확인했으며, 이어 아래의 실제 체결·헷지 제한 시험도 완료했다.

후속 실측: 별도 승인받은 현재 시험 잔고용 시험에서 LIT 4개를 양쪽 반대로 체결하고 reduce-only로 전량 정리했다(`docs/PAIRED_TRIAL.md`). 총 4건·추가 전송 0건, 최종 포지션과 활성 주문은 모두 0이다. 시험 전후 순비용은 0.151225 USD였다.

현재는 Codex가 주 담당이다. 열린 주문 60초 대사와 실제 open 확인 로그를 추가했고 테스트 247개가 통과했다. 2026-10-30에는 승인받은 500달러 설정의 메인 10분 시험을 완료했다. 체결 19건·헷지 18회가 확정됐고 종료 후 활성 주문·미확정은 0이다. 양쪽 헷지 포지션은 유지했고 종료 직후 평가 자산 변화는 -1.310360 USDC였다. 상시 운영은 시작하지 않았다. 데드맨의 강제 종료 후 취소와 달리 ping 유지 중 타이머 연장 실측은 미검증으로 남긴다(`docs/LIVE_10MIN_RESULT.md`).

## 목표

### 1주차: 측정

수익이 목표가 아니다. 아래 두 숫자를 실제로 재는 게 목표다.

1. 호가 1,000달러를 1시간 걸었을 때 받는 리워드 (마켓별)
2. 체결 1건당 헷지 비용

이 두 숫자가 나오면 이 전략이 되는지 안 되는지 판단할 수 있다. 지금 가진 수익 추정은 리워드 배분 공식을 모르는 상태의 가정일 뿐이다.

### 현재 1주 공개 비교의 판단 (2026-10-30 변경)

기준 자본500USD에서 비용 차감 후 주2USDC 순이익이 사용자 기준이다. 단순 연 환산 약20.8%이며 실제 수익이나 재투자 수익 보장이 아니다. 기존 월3% 확대 기준 대신 이번 비교에는 아래 기준을 적용한다.

| 결과 | 다음 행동 |
|---|---|
| 같은 거리·모형의 BTC+ETH 주간 순이익 가정 범위가2USDC 이상 | 계속 검증할 후보로 검토. 실주문·자본 확대는 별도 승인 |
| 가정 범위 전체가2USDC 미만 | 수정 또는 중단 검토 |
| 모형 범위가2USDC를 걸치거나 자료 부족 | 판단 유보, 부족한 근거 확인 |
| 손실 또는 모형 위험 정지 | 원인을 기록하고 재개·확대하지 않음 |

## 운영 조건

| 항목 | 값 |
|---|---|
| 자본 | 비교 기준500USD. 거리별 모형은 독립된 대안이며 수익을 합산하지 않음 |
| 레버리지 | Ondo 시작 시 3배 설정. Lighter 설정값은 3이지만 현재 코드는 별도 변경 API를 호출하지 않음 |
| 1주차 마켓 | BTC·ETH 공개 비교만 진행. LIT·ENA는 이번 주 유동성 대상이 아니며 잔여 포지션 정리 완료 |
| 한쪽당 호가 | 60달러 (Lighter 최소 주문 10달러를 한 번에 헷지할 수 있는 크기) |
| 정지 기준 | 헷지 안 된 노출 40달러 20초, 자산 감소 25달러, 전체 재고 350달러. 최대 손실 보장이 아니라 호가를 멈추는 기준이다 |
| 운영 장소 | 집 PC. PC를 끄면 관측 중단, 실주문 자동 재시작 없음 |

초기500USD·LIT/ENA 선택은 얇은 호가를 기준으로 한 가정이었다. 현재 공식 주간 대상에서 제외된 사실을 확인해 그대로 운영하지 않는다. 자본 규모만으로 리워드 액수를 보장할 수 없다.

25달러는 최대 손실 보장이 아니다. 자산은 약 1분 간격으로 조회하므로 그 사이 손실이 기준을 넘을 수 있고, 정지해도 헷지된 포지션은 남아서 두 거래소 가격 차이 변화와 펀딩에 계속 노출된다. 헷지가 깨진 상태로 급변이 오면 손실은 25달러보다 커질 수 있다. 25달러는 "여기서 호가를 멈추고 사람이 확인한다"는 기준이다.

과거 호가 두께만으로 보상 수익을 단정하지 않는다. 이번 비교는 공식 대상인 BTC·ETH의5/10/18bps를 대상으로 보상 비중과 체결·헷지 비용의 관계를 모형으로 검토한다. 실제 지급과 자기 주문 체결은 별도 실측 전까지 미확인이다.

## 하지 않는 것

- 방향성 베팅. 헷지 안 된 포지션은 사고로 취급한다.
- 속도 경쟁. Lighter는 주문이 0.3초 늦게 들어가므로 체결을 많이 받는 전략은 손해다.
- Ondo에만 있는 마켓(BRENT, NFLX, SMSN 등). 헷지가 안 된다.
- Variational 자동화. API 거래가 아직 안 열려 있어서 수동 소액으로 따로 한다.

## 가장 큰 위험과 대응

| 위험 | 대응 |
|---|---|
| 헷지 한쪽만 열린 채 방치 | 현재 500달러 설정은 헷지 안 된 노출 40달러·20초를 호가 정지 기준으로 사용 |
| 헷지 주문 결과를 모름 | 같은 마켓의 재전송 차단, 10초 후 모든 Ondo 호가 일시정지. 미확정은 SQLite에 보존하고 재시작해도 복원 |
| 봇이나 PC가 갑자기 죽음 | Ondo 데드맨 스위치: 30초 안에 호가 자동 취소 |
| 같은 이름인데 다른 자산 | 두 거래소 가격 차이가 1%를 넘으면 제외 (OPENAI, ZHIPU 사례). 평소 차이에서 0.15% 이상 벗어난 마켓도 호가 중단 |
| 리워드 규칙 변경 | 베타라 언제든 바뀔 수 있음. 매주 리포트로 확인 |
| API 키 유출 | 출금 권한 없는 키, IP 화이트리스트, 키는 `.env`에만 |
