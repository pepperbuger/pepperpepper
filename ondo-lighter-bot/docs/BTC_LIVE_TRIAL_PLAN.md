# BTC 10분 소액 시험 계획 — 승인된1회 실행 완료

2026-11-03 사용자가 아래 구체 범위의 실제 주문 시험1회를 명시적으로 승인해 실행과 정리를 완료했다. [실행 결과](BTC_LIVE_TRIAL_RESULT.md)는 최종 포지션/활성주문/미확정0·총비용0.034696USDC다. 이 승인은 소진됐다. 아래는 당시 준비·승인 범위를 보존한 계획이며 새 실행 승인이 아니다. 실제 Lighter 계정은 사후 조회에서 Premium으로 확인됐으므로 기존 Standard/수수료0 가정은 다음 live에 사용하지 않는다.

## 이번 주 확인한 내용

[공식 Rewards](https://app.ondoperps.xyz/rewards)를 로그인 없이 직접 확인했다. Week2 총250,000USDC, 유동성112,500USDC, 거래량112,500USDC, 액티비티25,000USDC다. 현재 UI의 유동성 설명은20개 대상·25bps 이내·한쪽 호가도 자격·5bps 안쪽85%를 명시하고 [20개 대상 목록](https://app.ondoperps.xyz/ko/announcements/usdc-rewards-upgrade)을 연결한다. 그 목록에는 BTC가 있다.

다만 연결된 글의 날짜/금액은 여전히 지난주다. 새 마켓별 배분액과 나머지 거리별 비중을 직접 확인하지 못했으므로112,500/20=5,625를 확정하지 않는다. `docs/rewards-eligibility-2026-11-03.json`은 현재 UI가 연결한 목록 중 BTC만 허용하는 **자격 확인 전용**이다. 유효기간은 공식 화요일00UTC 주간 규칙과 Week2 카운트다운에 따른11월3일00UTC~11월10일00UTC다. 일반 금액 모형 loader는 이 파일을 거부한다. 기존 공개 비교 정책은 그대로 만료 상태다.

## 실행을 요청할 구체 범위

| 항목 | 범위 |
|---|---|
| 마켓·시간 | BTC 한 마켓, 호가 운영10분, 이후 자동 상시 재시작 없음 |
| Ondo 호가 | post-only 매수/매도, 한쪽 목표25USD, 현재 단위로 각0.0003BTC·약23.2USD. 시세에 따라 수량을 다시 내림 |
| 거리 | 중간가에서4bps 목표·재호가 기준1bps. 이동/지연 때문에 항상5bps 안이라고 보장하지 않음 |
| Lighter 헷지 | 체결된 반대 방향 IOC,15bps 가격 보호, 확실히 거절된 요청만 판단. 시험 설정 retries=1 |
| 중단 기준 | 재고50USD, 시작 자산 감소5USD, 미헷지15USD 초과20초, 시세/포지션/주문 오류 시 기존 안전장치 |
| 시작·종료 | 실행 직전 양쪽 포지션·활성 주문·운영 DB 미확정0 재확인, Ondo 초기/종료 호가 취소와30초 데드맨 |
| 레버리지 | 메인 엔진이 Ondo BTC를3배로 설정하는 요청 포함. Lighter 계정 등급/레버리지 변경은 하지 않음 |
| 종료 후 정리 | 확인된 BTC 잔량만 reduce-only IOC, 거래소별100USD 이하·20bps 보호·정리 비용 예산2USD·합계 최대2건 |
| 결과 불명 | 새 헷지/정리 주문 재전송 금지. 부분 정리나 한쪽 잔존이면 즉시 보고하고 중단 |

50USD와5USD는 **중단 기준**이며 최대 노출·손실 보장이 아니다. 마지막 남아 있던 호가의 체결, 조회 지연, 가격 차이·급변으로 넘을 수 있다. 정리2USD는 정리 직전 참조가 대비 실행비용 예산이며 전체 시험 손실 상한이 아니다. 최소 주문·가격 보호·깊이가 맞지 않으면 정리를 강행하지 않는다.

입출금·이체·키 등록·계정 등급 변경, 다른 마켓 정리,10분 이후 상시 운영은 포함하지 않는다. 같은 계정에 수동 주문/다른 봇을 동시에 쓰지 않는다.

## 준비·검증 결과

- 작업본·설치본 전체 **351개 테스트 통과**.
- 실제 키 인증·실제 주문 응답 형식·주문 번호 재조회8개 모두 통과. 키는 D설치본 `.env`에서만 읽고 출력·커밋에 남기지 않았다.
- 양쪽 비영 포지션·활성 주문0, 운영 미확정0. 기존 실제 시험 기록은 제자리에서 읽기 전용 검증했다.
- `check-config --online` 통과. 실제 공개 깊이로 BTC0.0003·매수23.1924/매도23.2113USD·거리약4.073bps를 확인했다. 이는 당시 가격이므로 실행 전에 다시 계산한다.
- 새 시험 설정으로 실제 시세30초·메모리DB 검증, 종료코드0·호가 표본58건·실제 주문0·거래 클라이언트 생성0·키 읽기0. 검증 보조 도구의 결과 기록 속성 오타는 수정 후 재검증했다.
- 실제 주문·취소·데드맨 활성·레버리지 변경은 모두0이다.

조회 중 공식 `accountOrders`가 최근24시간/종료1,000건만 지원해10월30일 주문을 찾지 못하는 것을 확인했다. 최근 종료 이력에서 같은 주문을 찾는 보완 후 실제 검사를 재통과했다. 찾지 못한 주문은 여전히 미확정이며 시간 경과로 재전송하지 않는다.

## 실행 및 기록 위치

사용할 별도 설정은 `config.trial-btc.example.yaml`이다. 기존 `config.yaml`, `.env`와 운영 기록을 교체하지 않는다. 실제 실행 시 D설치 폴더에서 기존 운영 DB를 사용해 미확정 보호와 이전 시험 검증을 유지한다. 정상적인 승인된 실행의 기록 추가만 허용한다.

완료한1회는메인엔진의 `run(duration=600)` 경로와기존운영DB를사용했다. 정리는새 `btc_cleanup.BtcNative`와 `execute(..., approved=True)`를별도새저널로한번만호출했다. 완료한BTC저널과과거LIT/ENA정리명령을재사용하지않는다.

task폴더 `outputs/btc-live-prep-20261103/`에준비근거를, `outputs/btc-live-trial-20261103/`에실제시험·정리저널을보존했다. 기존공개수집기5개는재개하지않았다.

10분 시험은 주문·체결·헷지·취소·비용 확인이며 주간 보상 지급이나 순수익 검증이 아니다. 실제 보상액은 해당 주 정산 후 따로 확인한다.
