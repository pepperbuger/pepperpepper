# BTC·ETH 5/10/18bps — 공개 데이터만 사용하는 7일 비교

실주문 재개 금지. 새 수집기는 비밀값·서명·주문 클라이언트를 import하지 않고 공개 GET과 WS subscribe/ping만 사용한다. 기존 18bps 5분 관측 기록은 보존한다. 체결/300ms 비교는 새 수집을 시작한 시점부터 604800초간 진행하며, 이전 저빈도 자료에서 고빈도 체결을 만들어내지 않는다. 정확한 시작·마감은 `comparison-launch.json`에 기록한다.

실제 비교 시작: **2026-10-30 20:43 KST**, 마감: **2026-11-06 20:43 KST**. 공개 WS 양쪽 연결·12개 모형·보상 첫 원본 저장·주문 0을 확인했다. 작업본/설치본 테스트 275개 통과. 기존 관측은 149회·오류 0 상태까지 보존했다. 매일 23:00 예약 점검은 중요한 변화 때만 알리고, 마감 후 6행 순이익 표를 검증해 보고한 뒤 예약을 삭제한다. PC와 네트워크가 유지돼야 한다.

## 공통 가정

- BTC·ETH 각각 거리 5, 10, 18bps, 한 방향 60 USD. 각 거리마다 독립된 가상 자본 500 USD다. 거리를 동시에 실주문하는 설정이 아니다.
- 두 마켓을 5초 어긋나게 10초 간격으로 재호가하며 취소·생성/대기 공백을 2초 가정한다. 이는 거리 비교용 통일 프로토콜이다. 현재 메인 봇의 6bps 재호가 임계값·재고 스큐를 그대로 재현한 것은 아니다. 이 결과만으로 메인 봇 수익을 입증했다고 하지 않는다.
- 5/10bps 경계는 안쪽 한 tick으로 정하고, 주문 수량은 두 거래소 공통 단위로 내림한다. 가상 post-only가 즉시 체결될 가격이면 생성하지 않는다. 자산당 재고 200 USD, 같은 거리·모형의 전체 재고 350 USD, 순노출 40 USD/20초·자산 감소 25 USD 정지 조건을 대입한다. 정지 후 가상 호가를 다시 켜지 않는다.
- 공개 Ondo 체결의 taker 방향·가격·수량을 이용한다. `touch`는 자기 가격에 닿은 체결, `through`는 자기 가격을 넘어선 체결만 인정한다. 체결량은 공개 거래량·남은 가상 주문량을 넘지 않는다. 두 모형의 차이는 시나리오 범위이지 실제 체결 확률의 신뢰구간이나 엄밀한 상하한이 아니다. 자기 주문의 큐 위치·취소·가격 영향은 알 수 없다.
- 부분 체결은 Lighter 최소 금액 10 USD에 여유 5%를 더한 기준에 도달하면 묶어 헷지한다. 그 미만은 공짜로 체결됐다고 처리하지 않고 남은 노출로 기록한다. 따라서 가상 체결 건수와 헷지 횟수는 다를 수 있다.

## 비용과 순이익

가상 헷지 결정 시각에서 **최소 300ms 지난 뒤 실제로 받은 Lighter 호가 상태**로 반대 방향 VWAP를 계산한다. 초기 체결의 수신 지연과 300ms 이후 첫 갱신까지의 시간도 기록한다. 호가 연결이 끊겼거나 nonce가 불연속이면 재구독해 새 스냅샷을 받는다. 깊이가 부족하거나 이후 시세를 못 받으면 비용을 0으로 메우지 않고 모형의 미확정/정지로 남긴다.

비용은 방향을 유지한 부호로 분리한다. 유리한 괴리는 음의 비용이 될 수 있으며 절댓값으로 손실 처리하지 않는다.

1. Ondo 체결가의 중간가 대비 우위: 가상 호가 수익.
2. 가상 헷지 결정 때 두 거래소 중간가 차이.
3. 소액 부분 체결을 누적하는 동안의 가격 변화.
4. 최소 300ms 지연 중 Lighter 중간가 변화.
5. Lighter 스프레드와 해당 수량의 호가 깊이.
6. Ondo maker 0.01%, Lighter Standard taker 0%. [공식 Ondo 수수료](https://docs.ondoperps.xyz/fees), [공식 Standard 지연·수수료](https://docs.lighter.xyz/developers/reference/account-types)

가상 매매손익은 양쪽 현금흐름과 잔여 포지션 평가로 계산한다. 위 성분들을 현금흐름에서 다시 차감해 비용을 중복 계산하지 않는다. 여기에 공개 예상 시간당 펀딩을 적분한 근사를 더하고, 종료 시 양쪽 반대 정리 VWAP와 Ondo taker 0.025% 비용을 빼 순손익을 표시한다. 펀딩은 실제 정시 지급 내역이 아니며 호가/시간대 자료가 부족하면 순이익은 **산출 불가**로 둔다. 0회 체결의 체결당 비용도 0이 아닌 산출 불가다. 종료 호가 깊이는 최근 공개 REST 스냅샷(최대 330초 전)을 사용하는 추정이다.

체결당 헷지 비용은 최종 가상 헷지에 포함돼 가격을 계산할 수 있는 `costed_fills`를 분모로 사용한다. 아직 누적 중인 소액·300ms 대기·시세 불명 체결을 0 비용으로 평균에 넣지 않는다. 전체 체결 수와 비용 계산에 포함된 체결 수를 함께 보존한다.

## 리워드

공식 공지의 유효 주간·대상을 확인한 정책만 적용한다. 현재 5/10/18bps가 각각 85%/10%/5% 구간을 목표로 하더라도, 실제 가상 주문의 남은 수량·거리·호가 공백에 따라 배분을 다시 계산한다. 약 45~75초 무작위 간격으로 Ondo 깊이를 조회해 주기적인 재호가 공백과 관측이 항상 같은 위상으로 겹치는 편향을 줄인다. 모든 Ondo REST는 하나의 1초 버킷을 공유한다.

`시장당 주간 풀 × 거리 구간 배분 × 자기 USD / (경쟁 USD + 자기 USD)`가 기존 비례배분 가정이다. 공식 세부 지급 공식은 아니다. 공지가 5~6bps·10~11bps 소수 경계를 명시하지 않아, 이 물량을 인접 버킷에 배치할 때의 범위를 계산한다. 100단계 깊이가 25bps까지 닿지 못하면 계산을 확정하지 않는다.

이번 주 정책은 11월 3일 09:00 KST에 만료한다. 확인되지 않은 다음 주 조건을 연장하지 않는다. 공지 확인이 늦어지면 그 구간을 미확인으로 표시하고, 당시 깊이·가상 주문을 압축 원본으로 보존해 확인된 해당 주간 정책으로만 재계산한다. 다음 주 수집을 재시작하거나 자료를 지우지 않는다.

## 결과와 한계

사용자의 최신 판단 기준은 **500 USD 자본으로 비용 차감 후 주2USDC**, 단순 연 환산 약20.8%다. 같은 거리·같은 체결 모형의 BTC+ETH만 합쳐 판정하고, 서로 다른 거리 대안의 가상 수익을 합산하지 않는다. 마지막 표에는 거리별 합계와 기준 이상/미달/모형 범위가 기준을 걸쳐 유보/자료 부족을 구분한다. 실제 수익이나 실주문 재개 승인을 뜻하지 않는다. 잔여 LIT/ENA는 별도 승인된4건으로 전량 정리 완료했다.

`summary.json`은 30초마다 현재 상태, `fills.jsonl`/`hedges.jsonl`은 가상 이벤트, `reward-inputs.jsonl.gz`는 보상 원본이다. 실제 수신 공개 메시지 fixture를 순수 파서 테스트에 사용한다. 프로세스는 7일 후 종료하며 `REPORT.md`와 `report-data.json`을 생성한다. 첫 표는 **BTC/ETH × 5/10/18bps 6행**, 각 행의 가상 체결 수·보상·체결당 비용·순손익을 touch/through 시나리오와 경계 불확실성을 포함해 보여준다. 아래에는 모형별 12행 상세가 있다.

주간 환산은 같은 시장 조건이 계속된다는 가정이며, 관측 중 모형이 정지하면 계속 거래한다고 환산하지 않는다. 데이터 누락·미확인 정책·펀딩 공백·미확정은 모두 표시한다. 1주 비교 이후에도 실제 지급·체결 큐·주문 왕복 지연은 별도 실측 전까지 미검증이다. 이번 작업은 실제 거래 승인을 추가하지 않는다.
