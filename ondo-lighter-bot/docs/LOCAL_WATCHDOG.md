# 로컬 점검과 장애 시 알림

2026-11-04 사용자가 정상 상태에서도 5분마다 Codex가 실행돼 사용량이 드는 방식을 바꾸라고 요청했다. ETH 5분 heartbeat 예약은 삭제했다. `file_watchdog.py`는 로컬 Python이 기본 10초마다 실행 기록과 PID를 읽는 프로그램이다. 정상 점검은 모델 호출 0, 거래소 요청 0, 키 읽기 0이다.

새 장애나 종료만 PC 알림·영속 이벤트 파일로 남긴다. 선택적으로 설치된 공식 `codex queue --thread ... --message ... --resume`를 한 번 호출한다. 기존에 알린 장애는 인수인계 시 중복 전달하지 않는다. 각 사건의 전송 시도는 먼저 기록하고, 응답 유실·타임아웃이면 다시 보내지 않는다. 주문·취소·정리·봇 재시작 기능은 없다. PC가 꺼지면 로컬 점검도 중단된다.

공식 근거: https://learn.chatgpt.com/docs/cli/reference 의 `codex queue`. `--resume`은 로컬 daemon/선택 서버가 있어야 하며, 재개 실패도 경고와 종료 코드0으로 끝날 수 있다. 이 PC에서 실제 장애/종료 전달 시도는 종료 코드0이지만 경고가 있었다. 따라서 **이 채팅을 자동으로 깨우는 전달은 아직 검증되지 않았다.** `queued_without_warning=false`, `delivery_to_model_proven=false`로 기록하며 성공이라고 표현하지 않는다. 이벤트 저장과 PC 알림 경로는 별도로 제공한다. 표시 여부는 Windows 알림 설정의 영향도 받는다.

실행 예시(읽기 전용이며 거래 시작 명령 아님):

```powershell
python -m olbot.file_watchdog <기존_시험_출력폴더> --interval 10
```

채팅 연결은 `--codex-exe <설치된_codex.exe> --thread <기존채팅_UUID>`를 추가한다. 새 거래 실행/새 계정 권한을 부여하지 않는다. 종료 상태를 확인하면 최종 이벤트를 남기고 점검기도 끝난다. 실행 중복은 `local-watchdog.lock`으로 막으며, 죽은 프로세스의 잠금도 임의로 지우지 않고 PID를 먼저 확인한다.

## 수정과 검증

- 메인 위험 판단에서 마켓별/전체 재고 초과를 실제 kill로 연결했다. 반대 헷지가 있어도 재고를0으로 상계하지 않는다.
- 상태 저장은 Windows 파일 읽기 잠금으로 인한 일시적인 교체 실패를 제한 횟수만 재시도한다. 지속 실패는 숨기지 않고 기존/임시 기록을 보존한다. 로컬 실행기 소스에는 감독 작업 종료 시 엔진 정지 신호도 추가했다. 소진된 실행기는 다시 실행하지 않는다.
- 전체 검사 중 기존 공통 요청 간격 테스트가 한 번 실패했다. 예약 시각과 실제 worker 시작 시각이 달라 간격이 압축될 수 있어 요청 완료 뒤 간격을 확보하도록 수정하고 지연 dispatch 재현 검사를 추가했다. 공개 수집기는 재시작하지 않았다.
- 로컬 점검의 정상 무호출·중복 억제·사라진 로그·종료 인식·전달 타임아웃·Windows 상태 저장·재고 정지를 주문 없는 테스트로 확인했다. 실제 주문으로 수정 코드를 다시 시험하지 않았다.
