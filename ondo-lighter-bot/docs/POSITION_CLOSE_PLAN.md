## 주문 방식과 한도

- 전부 **reduce-only IOC**로 기존 포지션만 줄인다. Ondo는 non-post-only 지정가 IOC, Lighter는 SDK `create_market_order(..., reduce_only=True)`의 가격 보호 한도를 사용한다. 무제한 시장가를 쓰지 않는다. 실행 직전 최우선 체결 가능 호가에서 추가 20bps 이내로 보호 가격을 정하고, 그 가격 안에 전체 수량을 채울 깊이가 있는지 확인한다. 네 가격 한도의 보수적 예상 비용 합계도 2 USD 이하일 때만 시작한다. 공식 [Ondo Create Order](https://docs.ondoperps.xyz/api-reference/orders/create-order)와 Lighter SDK의 기존 정리 경로를 근거로 한다.
- 총 전송 최대 **4건**, 주문당 명목 금액 최대 **200 USD**다. **추가 정리 비용 예산은 합계 2 USD**로 제안한다. 이는 주문 전 현재 중간가 대비 호가 깊이·수수료·가격 보호 한도로 계산하는 실행 조건이며, 한쪽 체결 후 급변이나 통신 유실까지 포함한 최대 손실 보장이 아니다. 이미 발생한 평가손익과 실행 전 펀딩은 이 추가 비용에 포함하지 않는다.
- LIT 한 쌍을 먼저, 그다음 ENA 한 쌍을 처리한다. Ondo가 최종 체결되고 포지션에 반영된 수량에 대해서만 Lighter 반대 정리를 한다. 두 거래소 원자적 동시 체결은 불가능하며 중간에 방향 노출이 생길 수 있다. Standard taker 300ms 지연도 있다.
- 일부 체결이면 확인된 체결량만 상대 거래소에서 reduce-only로 정리하고 잔여 수량을 보고한다. 상대 거래소 최소 주문 미달 또는 한쪽만 체결되면 임의 추가 주문 없이 멈춘다. 결과 불명은 재전송하지 않고 조회만 하며, 해결 전 다음 마켓으로 진행하지 않는다. 4건 내 전량 정리가 안 되면 추가 승인을 받는다.
- 주문/고유 번호와 전송 여부는 발송 전에 새 별도 정리 기록에 남긴다. 기존 운영 DB·시험 기록을 지워 통과시키지 않는다.

## 예상 비용과 실행 직전 조건

위 호가의 양쪽 중간가 대비 예상 추가 비용은 **약 0.8135 USD**: Ondo 수수료 **0.04924 USD**, 네 주문의 스프레드·깊이 비용 **0.76427 USD**다. Standard Lighter taker 수수료는 0으로 가정하며 TWAP를 사용하지 않는다. [Ondo 수수료](https://docs.ondoperps.xyz/fees), [Lighter Standard](https://docs.lighter.xyz/developers/reference/account-types)

LIT Ondo 매도 호가가 얇아 이 비용이 크다. 호가를 새로 읽어 각 주문의 보호 가격 안에서 승인 수량이 전량 가능한지와 합계 2 USD 예산을 확인한다. 20bps를 추가 가격 변화 민감도로 적용하면 약 0.79 USD가 추가되는 시나리오이나 이는 상한 보장이 아니다. **예산·깊이 조건을 못 맞추면 주문하지 않는다.** 기존 손실을 여기서 다시 비용으로 합산하지 않는다.

실행 전에 실주문 봇 정지, 계정·마켓·포지션 일치, 활성 주문 0, 미확정 0을 확인한다. 공개 비교 관측의 `PAUSE_REST`를 켜고 `REST_ACTIVE`가 사라진 뒤 최소 1.1초 기다려, 정리/조회도 Ondo 초당 1회 예산으로 직렬화한다. WS 비교 관측과 기존 기록은 보존한다.

종료 후 두 번의 계정 조회로 양쪽 최종 포지션·활성 주문, 각 주문의 최종 상태와 체결 수량, 전후 자산 변화·명시 수수료를 보고한다. 잔여 포지션·불명확 상태가 있으면 정확히 표시한다. 이 범위는 승인받아 실행 완료했으며 **추가 주문은 새 별도 승인 전 실행하지 않는다.**
