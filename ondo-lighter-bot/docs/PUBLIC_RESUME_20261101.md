# 11월 1일 공개 비교 재개 결과

사용자가 다른 프로젝트의 관측기에도 공통 요청 한도를 적용하고 공개 수집을 재개하도록 승인했다. 실주문은 꺼져 있으며 키·서명·계정 조회는 사용하지 않았다. 기존 `.env`, `config.yaml`, 거래 `data/`와 실제 시험 기록은 읽거나 바꾸지 않았다.

PID는 이 실행의 기록이며 이후 생존 여부를 보장하지 않는다. 두 묶음의 `comparison-launch.json`, `funding-launch.json`과 실제 명령행·새 표본을 함께 확인한다. 작업자 자동 재시작은 추가로 승인되지 않았다.

Ondo 비교 마감은 **11월 6일 20:43 KST**로 유지한다. 별도 프로젝트의 원래 14일 마감(11월 15일)은 변경하지 않았다. Ondo 점검 예약 종료가 별도 프로젝트 관측기까지 종료한다는 뜻은 아니다.

## 보존과 요청 예산

기존 BTC/ETH의 12개 모형에서 처음 복구된 summary가 이전 summary의 수량·체결·헷지·수수료·비용 성분·위험 정지와 정확히 일치했다. 가상 현금흐름은 원본 이벤트로 복원했고, 펀딩 `first_seen`과 초기 비용 기준도 유지했다. 중단 두 구간은 그대로 남는다. 누락 시세나 가상 체결을 소급 생성하지 않았다.

별도 공개 관측기의 기존 DB 27,868개 행을 일관된 읽기 전용 스냅샷으로 보존한 뒤, 승인된 작업자만 한 번 종료·수정·재개했다. 죽은 작업자의 실행 잠금만 확인 후 해제했다. 공개 DB·압축 원본·기존 규칙·마감은 보존했으며 재개 후 행 증가를 확인했다. 요청 대기 뒤 누락된 시각을 따라잡으려고 조회를 몰아서 보내지 않는다.

다섯 작업자는 원래 BTC/ETH `comparison/` 폴더의 OS 잠금과 1.1초 목표 간격을 공유한다. 시작 검증에서 실제 Ondo GET 간격의 최솟값은 약 **1.083초**로 초당 1회 한도를 지켰다. `PUBLIC_REST_REQUESTS.jsonl`에 공개 URL·시각·PID만 남긴다. 신규 깊이는 `depthBooksPerps` WS를 사용하며, 펀딩 조회는 같은 공유 예산과 pause 소유권을 사용한다.

## 확인한 것과 아직 없는 것

- 작업본·D 설치본 각각 pytest **333개 통과**. 별도 프로젝트 계산 검증 **9개 통과**.
- 별도 관측기에서 공통 GET 경로와 429 대기 처리를 모의 응답으로 검증했다. 실제 검증 주문은 0건이다.
- 두 묶음에서 양쪽 WS의 새 메시지와 증가하는 깊이/보상 표본을 확인했다. 다섯 작업자의 활성 stderr는 비어 있고 펀딩 조회 오류도 0이었다.
- 기존 펀딩은 BTC/ETH 각각 47개 일치 시간으로 보충됐다. 중단 동안 확정 비율을 얻었다고 그 시간의 가격·체결·펀딩 현금흐름까지 확인된 것은 아니다.
- 신규 6개는 시작 전 확정 펀딩 이력을 각 거래소에서 불러왔다. 첫 검증 시에는 시작 후 정산 시간이 아직 없어 누적 일치 시간이 0이다. 이를 한 주 펀딩 수입 0으로 해석하지 않는다.

기존 BTC/ETH 전체 기간 순이익은 중단 때문에 산출 불가다. 신규 TradFi는 약 5일의 별도 관측이며, 7일 실측으로 표시하지 않는다. NVDA 등 시세가 오래 갱신되지 않은 표본은 누락으로 남긴다. 초기 보상 원본에서 어느 후보의 값이 커 보여도 실제 지급이나 실제 헷지 수익 검증은 아니다.

미국 주식의 정규장·정규장 밖·주말/휴일을 구분한다. 각 TradFi 마켓은 자본 500 USD의 독립 대안이며 서로 수익을 더하지 않는다. 확정 펀딩을 같은 가상 재고에 반영해 기존 예상치와 교체하고, 비용은 중복 차감하지 않는다. 현재 보상 주간은 11월 3일 09:00 KST 만료하므로 다음 주를 확인하기 전에는 연장하지 않는다.

## 로컬 증거

아래 경로는 이 채팅 task 폴더 기준이다. 공개 관측 원본은 용량 때문에 Git에 포함하지 않는다.

- `outputs/reward-week-20261030/resumes/20261101/`: 이전 launch·체크포인트·펀딩 사본, 복구 증거, 현재 로그와 `startup-validation.json`.
- `startup-preservation-proof.json`: 첫 복구 모형의 수량·비용·위험 상태 일치.
- `outputs/tradfi-budget-coordination-20261101/`: 별도 관측기의 수정 전/후 코드·diff·DB 스냅샷·재개 기록·모의 경로 검증.
- 각 묶음의 `comparison/REPORT.md`, `report-data.json`, `funding/FUNDING_REPORT.md`, `funding-data.json`.

PC와 네트워크가 유지돼야 수집이 계속된다. 작업자가 다시 중단되면 새 공백을 기록하고 알리며 자동으로 재시작하거나 실주문을 켜지 않는다.
