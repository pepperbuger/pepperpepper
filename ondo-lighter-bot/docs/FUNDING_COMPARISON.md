# 공개 펀딩 차이 관측과 순이익 합산

2026-10-31 재개 승인: 작업자 종료 이후의 확정 펀딩은 공개 이력으로 보충할 수 있지만, 그 시간의 시장 깊이/중간가/가상 체결을 새 관측으로 만들지는 않는다. 재개 시 기존 `first_seen`·오류 이력·처음의200USD 쌍 진입 기준을 보존한다. 중단 중 Ondo 기준가격이 없으면 해당 보유 펀딩과 전체 합계는 산출 불가로 남기며, 비율의 통계와 수익 계산 가능 여부를 구분한다. 실제 주문·키 사용은 없다.

실주문 재개 없음. 키·서명·계정 API 없이 BTC·ETH 공개 확정 펀딩만 수집한다. 기존 비교 시작(2026-10-30 20:43 KST)부터의 지급 이력을 보충하고, **2026-11-06 20:43 KST** 마감까지 매 UTC 정각5분 후 갱신한다. 출처 발표가 늦거나 조회에 실패하면 해당 시간을 누락으로 남기고 다음 조회에서 이력으로 보충한다. 과거 원문과 오류 기록은 보존한다. 가상 가격 수집기와 실주문 봇을 재시작하지 않는다.

## 근거와 단위

- [Ondo 시간당 펀딩](https://docs.ondoperps.xyz/funding-rates): UTC 정각 후 첫 tick에 정산한다. 양수이면 롱이 내고 숏이 받는다. 실제 지급의 명목 기준은 oracle 가격이다.
- [Ondo 이력](https://docs.ondoperps.xyz/api-reference/funding-rate/get-funding-rate-history): `GET /v1/perps/funding_rate_history`, `market`, `startTime/endTime` UTC ms, `limit/cursor`. `fundingRate`는 시간당 소수 비율이다. 실제 `time`의 소수 초도 보존해 가상 재고와 맞춘다. 완결되지 않은 페이지를 완료로 보지 않는다.
- [Lighter 이력](https://docs.lighter.xyz/api/funding/fundings): `GET /api/v1/fundings`, `market_id`, `resolution=1h`, `start_timestamp/end_timestamp` 초, `count_back`. 실제 응답과 같은 시각의 signed WS 펀딩을 대조했다. `rate`는 percent 크기이며 `direction=long`은 양수, `short`는 음수로 바꾼 후100으로 나눈다. `value`는 그 방향의 기초자산1개당 펀딩 지급 크기다. 알려지지 않은 방향·단위·필드 누락은0으로 메우지 않는다.
- [Lighter 펀딩](https://docs.lighter.xyz/trading/funding): 시간당 지급, 양수는 롱이 낸다. 처음 요청한 `apidocs.lighter.xyz/llms.txt`가 이동해 연결된 현재 `docs.lighter.xyz/llms.txt`에서 확인했다.
- 실제 Lighter `count_back=200` 응답은 시작 시각보다 이른 자료도 반환했다. 원문을 보존하고 목표 시간 바깥 과거·미래를 필터한다. 이 문제를 수정하기 전 실패 표본도 로컬에 보존했다.

두 거래소 모두 **시간당 소수 비율**로 통일한다. 8시간 환산은 동일한 비율이8시간 유지된다는 참고 계산이며 실제8시간 지급률과 혼동하지 않는다. 통계는 `Ondo−Lighter`다. 평균·중앙값, 양/음/0시간 수, 우세 부호 비율, 최장 같은 부호 연속 정산 구간을 기록한다. 누락·중립0은 연속 부호를 끊는다. 우세 비율의 분모는 두 거래소가 모두 있는 시간이며 전체 기대 시간과 누락 수를 함께 표시한다. 시간 중의 예상 비율 변동을 계속 같은 부호였다고 단정하지 않는다.

## 초기 200USD 쌍 보유 비교

원래 시작 직전의 마지막 확정 시각 차이로 방향을 한 번 고정한다. 이후 매시간 결과를 보고 유리한 방향으로 뒤집는 사후 계산을 하지 않는다. 과거 시점의 실제 API 공개 지연까지 소급 증명한 것은 아니므로 그 가정도 표시한다. 신호가0이거나 양쪽 자료가 없으면 임의 방향을 만들지 않는다.

각 자산별로 두 거래소 **같은 기초자산 수량**을 사용한다. 초기 명목이 양쪽 각각200USD 이내가 되도록 거래소 공통 단위로 내리므로 BTC/ETH 각각의 정확한 명목은200보다 작을 수 있다. 고정200USD 명목의 비교값 `200×Σ(시간당 차이)`와168시간 환산은 별도 참고 필드이며, 실제 같은 수량을 보유하면 가격에 따라 명목이 변한다. 두 자산200USD 쌍은 별도의 대안으로 보며 추가 자본처럼 합산하지 않는다.

처음의 공개 호가와 매시간 공개 깊이에서 진입·정리 VWAP/수수료를 추정한다. 독립 비교표는 taker 진입/정리를 가정하고, 기존 maker 가상 체결표에는 그 진입 비용을 다시 더하지 않는다. 초기 두 거래소 호가 시각 차이와 미관측 전송 지연은 남아 있으므로 이 비용을 실제 왕복 비용이나 엄밀한 상한으로 표시하지 않는다.

같은 수량의 반대 포지션이어도 `수량×[(Ondo−Lighter) 종료 차이−시작 차이]`의 평가손익이 남는다. 따라서 보고서에는 **펀딩 수입 → 진입/정리 비용 차감 → 별도 가격 차이 변화 → 합계 모형**을 나눠 표시한다. 진입은 무료가 아니며 한쪽 청산·증거금·전송 실패 위험을 제거하는 것도 아니다. 증거금의2배 같은 상한만으로 청산 방지가 보장되지 않는다. 명목 대비 연 환산과500USD 전체 자본 수익률도 구분한다.

## 기존 6행 표와 합산

기존 모형에는 이미 예상 펀딩을 연속 적분한 항목이 있었다. 여기에 새 펀딩을 한 번 더 더하지 않는다. 원래 예상치는 별도 보존하고 다음 방식으로 **교체**한다.

1. `fills.jsonl`과 `hedges.jsonl`의 가상 이벤트를 재생해 각 거래소 실제 지급 시각 직전의 모형 재고를 구한다. 두 거래소 지급 시각은 다를 수 있다.
2. Ondo는 확정 비율×그 직전 공개 중간가(최대90초 전)를 사용한 추정이다. oracle 가격과 정확히 같다고 주장하지 않는다. Lighter는 이력의 부호 있는 기초자산당 `value`를 이용한다.
3. `평가 매매손익 + 가정 리워드 − 종료 비용`에 같은 가상 재고의 위 펀딩만 더한다. 원래 매매손익에 들어간 maker/헷지 비용을 중복 차감하지 않는다.
4. 따로200USD 쌍을 강제로 더해 같은500USD 자본 가정을 깨지 않는다. 가상 재고가0이면 지급액0임을 알 수 있지만, 비율 누락은 원본 시간표에 여전히 누락으로 표시한다.

보고서는 BTC·ETH ×5/10/18bps **6행 표에 확정률 기반 펀딩 열**을 넣고, 별도 시간표/200USD 기준표/모형별12행 내역도 보존한다. 판단 기준은 같은 거리·모형의 BTC+ETH **주2USDC 순이익/자본500USD**다. 현재 짧은 관측을 확정 주간 수익으로 바꾸지 않는다. 기준 이상이어도 실제 수익 검증이나 실주문 재개 승인을 뜻하지 않는다.

원래 가상 호가 프로토콜은 유지한다. 펀딩 방향으로 호가를 기울이거나 강제로200USD를 추가 진입한 것으로 바꾸지 않는다. 이 때문에 원래 모형의 가상 재고가 없으면 펀딩 이익도 없다. 출구 비용 표본이90분 넘게 갱신되지 않으면 그 비용·합계는 산출 불가로 표시한다.
