# 500달러 설정의 10분 live 시험 계획

2026-10-29에 준비했고 2026-10-30 사용자 승인으로 실행을 완료했다. 결과는 [LIVE_10MIN_RESULT.md](LIVE_10MIN_RESULT.md)에 있다. 아래는 당시 승인 범위와 관찰 계획이며, 같은 범위의 자동 반복·상시 운영 승인은 포함하지 않는다.

## 사전 확인

- 열린 주문 대사: 공식 Get Orders의 `GET /v1/perps/orders?status=open&limit=1000`을 60초 간격으로 사용한다. 누락을 제거하고 다음 호가 루프에서 위험 조건 확인 후 재호가한다. 불일치는 `호가 대사 불일치`와 ledger의 `quote_mismatch`로 남긴다.
- 실제 확인 로그: 대사 성공 때 `호가 대사 확인: LIT tracked=2 open=2 exchange_total=2 | ENA ...` 형태로 기록한다. `open`은 현재 추적하는 주문 번호가 거래소의 열린 주문 응답에 실제로 존재하는 개수다. 미추적 주문을 이 수에 포함하지 않는다.
- 첫 대사는 live 루프 시작 약 60초 뒤이며, 조회에 걸린 시간을 빼고 다음 60초 주기를 유지한다. 초과 지연이 생겨도 놓친 주기를 몰아서 실행하지 않는다. 동일한 REST 버킷으로 초당 최대 1회를 지킨다. `verify-keys` 조회 버킷도 capacity=1이다.
- 설치 폴더의 `config.yaml`은 `config.live-500.example.yaml`의 정확한 복사본으로 준비했다. 이전 설정은 로컬 `data/config-backups/`에 보존했다. 설정 모드는 live지만 아래 명령은 아직 실행하지 않았다.
- `check-config --online`과 `verify-keys` 8개 항목이 통과했다. 실제 주문 응답 형식·번호 재조회도 포함한다. 양쪽 가용 잔고 각각 250 USDC 이상, 포지션·활성 주문 0, 기존 미확정 헷지 없음, 이전 제한 시험 기록 통과를 조회로 확인했다. 원본 잔고는 원격에 커밋하지 않는다.
- 실행 직전 다시 조회하여 잔고·포지션·주문·미확정 상태가 바뀌지 않았는지 확인한다. 키·운영 DB·기존 시험 기록을 삭제하거나 교체하지 않는다.

## 승인할 실제 동작

```
python -m olbot run --live --duration 600
```

- Ondo LIT·ENA에 각각 매수와 매도 한쪽당 약 60 USD, 시장가 기준 18bps 거리의 post-only 호가를 반복 갱신한다. 네 호가 합계의 목표 명목가는 약 240 USD다. 체결분은 Lighter에서 반대 IOC로 헷지한다.
- 시작 시 Ondo 기존 주문 전체 취소, LIT·ENA의 Ondo 레버리지 3배 설정, 포지션 대사와 데드맨 30초 활성화가 포함된다. Lighter 레버리지 변경 API는 현재 시작 코드에서 호출하지 않는다.
- 위험 설정은 헷지 안 된 노출 40 USD·20초, 연속 헷지 실패 3회, 시작 대비 자산 감소 25 USD, 전체 재고 350 USD다. 25 USD는 호가 정지 기준이며 최대 손실 보장이 아니다.
- 정상 10분 종료 시 Ondo 호가를 취소한다. 체결로 생긴 양쪽 헷지 포지션은 유지될 수 있다. 포지션 전량 정리는 이 명령의 종료 동작에 포함하지 않는다. 출금·이체·키 등록은 포함하지 않는다.

## 실행 중 점검과 종료 보고

1. live 루프의 약 1분·5분 시점에 `호가 대사 확인` 로그와 실제 REST 응답의 open 수를 확인한다. 호가 계산 로그만 보고 실제 주문이 열려 있다고 판단하지 않는다. 해당 시점에 호가가 없거나 조회에 실패하면 그 사실을 그대로 기록한다.
   데드맨의 heartbeat 연장은 별도 판정이다. 주문 교체 전후를 같은 주문으로 세지 않고, 같은 orderId가 30초 제한을 넘어 open으로 남아 있는지 실제 응답의 생성 시각·재조회 시각과 비공개 WS 연결/heartbeat 상태를 대조한다. 1분·5분에 서로 다른 새 주문이 존재한다는 사실만으로 연장을 입증했다고 말하지 않는다. 모든 주문이 30초 전에 재호가되면 이 항목은 미검증으로 남긴다. 별도 유지 시험을 위해 호가 교체를 멈추거나 추가 주문을 보내는 행동은 이 계획에 포함하지 않는다.
2. 이번 live 실행의 시작 시각을 기준으로 ledger와 로그를 구분한다. 기존 dry_run의 호가 스냅샷을 이번 시험에 합산하지 않는다.
3. 종료 뒤 양쪽 실제 포지션·Ondo 열린 주문·Lighter 활성 주문·미확정 헷지를 다시 조회한다. 잔고도 다시 읽어 시작 대비 변화를 확인한다.
4. 호가 노출 시간과 USD-시간(현재 30초 스냅샷 기반의 근사임을 표시), 체결 건수, 헷지 접수·최종 체결/실패/미확정 결과, `quote_mismatch` 발생 횟수, 양쪽 자산 변화와 남은 포지션을 보고한다. 헷지의 pending 기록과 final 기록을 별개의 주문으로 중복 합산하지 않는다.

코드·모의 검증은 전체 247개 테스트를 통과했다. 이 준비 과정에서 주문·취소·레버리지·데드맨 변경은 실행하지 않았다.

이 계획의 실행과 상시 운영은 각각 사전 승인이 필요하다. 담당자가 Codex로 바뀌었다는 요청만으로 실주문 승인이 주어진 것으로 해석하지 않는다.
