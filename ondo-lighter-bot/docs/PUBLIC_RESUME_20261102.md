# 11월 2일 PC 재가동 후 공개 관측 재개

사용자가 PC를 켰다고 알려 이전에 합의한 공개 관측을 07:29 KST 한 번 재개했다. 실제 거래는 꺼져 있다. 키·서명·주문·기존 실제 설정·거래 기록에는 접근하지 않았다.

## 보존과 확인

- 밤사이 마지막 시세 기록은 11월 1일 23:13:49~50 KST였다. 약 **8시간 15분** 공백을 각 모형과 `interruption_gaps`에 남겼다.
- 기존 BTC/ETH 12개와 TradFi 36개 모형에서 저널의 체결 수·수량·수수료·헷지 비용 합계가 저장 상태와 정확히 맞았다. 가상 현금흐름·재고·위험 정지를 복원했으며 포지션을 0으로 초기화하지 않았다.
- TradFi CLI에 `--resume-hedged`를 추가했다. 기본 명령으로 기존 자료를 덮어쓰지 못하고, 재개 플래그가 있어도 수량이나 저널이 불일치하면 거부한다. 회귀 검증 포함 작업본·설치본 각각 **335개 테스트 통과**.
- 재개 직후 첫 summary가 이전 48개 모형의 수량·체결·비용·위험 상태와 일치함을 확인했다. 기존 펀딩 `first_seen`과 초기 진입 비용 원본도 보존했다.
- 다섯 공개 작업자에서 새 시세와 표본 증가를 확인했다. 펀딩 비율은 기존 BTC/ETH 118개 자산-시간, TradFi 72개 자산-시간으로 보충됐고 비율 누락은 0이었다. 예전 오류 카운터는 보존했으며 재개 후 추가 오류는 없었다.
- 공유 Ondo GET 간격은 시작 검증에서 최소 약 1.089초였다. 기존 원본·정책·압축 이력과 별도 프로젝트의 공개 DB를 보존했다.

위 수치는 시작 검증 당시 기록이다. 누락 시간의 가격·가상 체결이나 펀딩 현금흐름까지 복구했다는 뜻은 아니다. 두 묶음 모두 중단된 전체 기간 순손익은 산출 불가로 유지한다.

## 실행 위치

기존 부모/자식 PID는 과거 기록이다. 현재 각 묶음의 `comparison-launch.json`, `funding-launch.json`과 실제 프로세스를 확인한다.

- `outputs/reward-week-20261030/resumes/20261102/`: 이전 launch·summary·펀딩 사본, 복구 증거, 현재 paper/funding stdout·stderr.
- `outputs/tradfi-week-20261101/resumes/20261102/`: 신규 후보의 같은 기록.
- `outputs/public-resume-20261102/`: 재개 승인 근거·과정·검증, 별도 공개 DB 스냅샷과 현재 external 로그·launch.
- `outputs/tradfi-budget-coordination-20261101/current-launch.json`: 별도 프로젝트의 현재 launch를 가리킨다. 같은 폴더의 옛 `restart.json`을 다시 실행하거나 현재 상태로 오인하지 않는다.

공통 요청 예산은 원래 BTC/ETH `comparison/` 폴더를 사용한다. 별도 프로젝트의 죽은 작업자 실행 표지만 프로세스 부재를 확인한 후 해제했다. DB·원본·규칙은 바꾸지 않았다.

## 기간과 정책

Ondo 두 묶음의 원래 시작과 **11월 6일 20:43 KST** 마감은 유지한다. 별도 프로젝트의 11월 15일 마감도 변경하지 않았다.

공식 공지 두 페이지를 재확인했고 `usdc-rewards-upgrade`는 10월 27일 버전 그대로다. 현재 대상·풀·85/10/5 비중을 유지하며 다음 주 조건은 아직 확인하지 않았다. **11월 3일 09:00 KST 이후 자동 연장하지 않는다.**

이번 1회 공개 재개 이후에도 작업자 종료 시 자동 재시작하거나 실제 주문을 켜지 않는다. PC가 꺼져 있던 시간은 기록에 계속 남긴다.
